# 代码题改用系统沙盒运行

2026-11-03 由你决定：代码题不再只靠 WebAssembly，改成用本机已装的语言，在系统沙盒里运行；缺哪种语言就提示安装。

## 结论

macOS 用系统自带的 Seatbelt（`sandbox-exec`）。实测这几种语言都能编译运行并通过测试用例：Python、JavaScript、C、C++、Rust、Swift、Java、Ruby。Go 写好了，但这台电脑没装，没有实测。

代码在 `crates/dem-sandbox/src/native.rs`（沙盒）和 `apps/desktop/src-tauri/src/coderun.rs`（各语言怎么编译、怎么运行、缺了怎么装）。

## 沙盒挡住了什么

规则从“全部禁止”开始，只开必要的：

| 项目 | 做法 | 测试 |
| --- | --- | --- |
| 联网 | 全部禁止 | 连外网失败 |
| 读个人目录 | 整个家目录和外接磁盘都不能读，只开放工具链自己的目录（如 `~/.rustup`） | 列出家目录失败 |
| 写文件 | 只能写这次运行的临时目录 | 写别处失败 |
| 系统服务 | 不能查询系统服务，所以读不到剪贴板，也打不开网页和别的软件 | 读剪贴板失败 |
| 启动别的程序 | 编译时允许（编译器要调链接器），运行答案时禁止 | 答案里 fork 失败 |
| 时间 | 每个用例 5 秒，加 CPU 时间上限 | 死循环判为超时 |
| 内存 | 每个用例 256MB，超了就停 | 申请 1GB 判为内存超限 |
| 输出 | 每个用例最多留 256KB | |

实测时发现一个坑：如果放开系统服务查询，代码就能通过 `pbpaste` 读到剪贴板。所以这一项一直关着。

## 缺语言时

界面显示“这台电脑还没装 X”，给一行安装命令和复制按钮。软件不替你运行安装命令，因为那会改动系统。

macOS 的 `/usr/bin` 里有几个占位程序（`python3`、`clang`、`swiftc`、`java`），没装开发工具时一调用就会弹出安装窗口。所以只有确认装了开发工具才会用它们，`java` 的占位程序永远不用。

## 会不会影响跨平台

会，但只影响这一处。Seatbelt 是 macOS 独有的：

- Linux 以后可以用 bubblewrap 或 Landlock 加 seccomp，Windows 用 AppContainer 加作业对象。都放在 `native.rs` 里，按平台各写一份。
- 还没写的平台上，`native_available()` 返回 false：Rust 照旧在 WebAssembly 里跑，其他语言提示“还不能运行”。
- Apple 把 `sandbox-exec` 标为过时已经很多年，但系统自己和很多开发工具还在用。哪天真被去掉，再换成 App Sandbox 加辅助进程。

## 和原方案比

WebAssembly 隔离更彻底，但每种语言都要随软件带一个编译成 WebAssembly 的运行环境，安装包会大很多，C 和 C++ 还要带一整套 wasi-sdk。系统沙盒直接用你本机的工具链，各语言的行为和你平时写代码时一样。
