# 技术验证 07：界面组件库（P0.5-05）

- 日期：2026-10-21
- 机器：Apple M1，macOS 26.6.2
- 前端：React 19.3.1、Vite 8.3.4、Node 26.10.0；Playwright 1.64.1（Chromium 156.0.8078.4，WebKit 27.2）
- 候选：react-aria-components 1.22.1、Radix UI（dropdown-menu 2.2.1 等 8 个包）、dockview-react 8.6.1、flexlayout-react 0.11.1、lucide-react 1.60.0、@phosphor-icons/react 2.1.10、three 0.186.1
- 代码与复现：`spikes/ui/`（见其 README）；原始结果：`spikes/ui/results/`
- **说明**：本次无人值守，屏幕锁着。Playwright 自带的 WebKit **不画 `backdrop-filter`**（下文“怎么验的”），Safari 的远程自动化开关要你在设置里打开，所以 WebKit 上的毛玻璃观感、Safari 的帧率和拖动手感还没测，已写进清单 `docs/spikes/checklists/07-ui-components-manual.md`。

## 要回答的问题

1. 无头组件库用 Radix UI 还是 React Aria：键盘操作、中文输入法、样式自由度。
2. 图标库用 Lucide 还是 Phosphor：风格、覆盖面。
3. 停靠布局用 dockview 还是 FlexLayout：能否完全套上我们的玻璃样式、能否守住“最多 3 × 3”、悬浮、拖动、保存恢复，在两种内核下的表现。
4. 液态玻璃的折射在 macOS 的 WKWebView（WebKit）上怎么做。
5. 首页星图加玻璃的性能。

## 怎么验的

- 同一组控件（菜单带子菜单、右键菜单、对话框、选择框、提示、页签、滑块，React Aria 另加组合框、自动补全、树）用两个库各做一遍，都套上 `theme.css` 的令牌。
- 同一个工作区（左栏两格、中间三个页签、右栏两格）用两个停靠库各搭一遍：玻璃皮肤、自定义页签（固定 ◆、预览斜体）、在拖放钩子里拦第 4 列和第 4 行、悬浮、保存再恢复。
- `probe/run.mjs` 用 Playwright 在 Chromium（≈ Windows 的 WebView2）和 WebKit（≈ macOS 的 WKWebView）里逐项操作，每项重新加载页面，按键之间停 120 毫秒（太快时 Radix 会忽略同一时刻的选择）。共 70 项，结果在 `results/probe-*.json`。
- 中文输入法：先用 `insertText` 输入中文看过滤；再模拟“组字中”（`compositionstart` 后发 `isComposing` 的回车），看会不会被当成选中。
- 折射：同一张带斜纹和大字的背景上放三块面板：A 普通 CSS 模糊；B CSS `backdrop-filter: url(#svg)` 的 SVG 位移滤镜；C WebGL 自己画背景，在面板范围内按离边缘的距离做透镜弯折和模糊，DOM 面板只负责文字、亮边、高光。
- 性能：three.js 星图（160 个星点、连线、溢光）铺满 1280 × 800（2 倍屏），上面叠 0 / 4 / 8 块玻璃面板，模糊半径 10 或 24，测 10 秒帧时间。用 Chromium 无界面模式加 `--use-angle=metal`（确认用的是 M1 显卡，不是软件渲染），再关掉垂直同步测余量。

### 4. 液态玻璃的折射

| 做法 | Chromium | WebKit |
| --- | --- | --- |
| A 普通 CSS 模糊 | 正常 | Playwright 的 WebKit 不画（见下），**真 Safari 待测** |
| B SVG 滤镜折射（`backdrop-filter: url(#…)`） | 正常，有波纹状折射 | **整条声明被丢掉，连模糊都没有** |
| C WebGL 自己画背景再折射 | 正常，边缘明显弯折 | 正常，边缘明显弯折 |

- Playwright 的 WebKit 无论有无界面都不画 `backdrop-filter`：同一块模糊面板下，Chromium 里像素起伏从 126 降到 2.6（被模糊了），Playwright 的 WebKit 里仍是 100 左右（没有模糊，只有白色蒙层）。所以 A 在 WebKit 下的截图不能说明真 Safari 的情况，留给清单。
- B 在 WebKit 下连模糊都没了，说明 CSS 里**必须先写一条只有模糊的 `backdrop-filter`**，再写带 `url()` 的那条。原型 E 就是这么写的。
- C 的限制：它只能折射我们自己画的东西（壁纸、首页星图）。菜单、启动器这类盖在正文文字上的浮层，后面是 DOM，没法用 WebGL 折射，只能用普通模糊。

截图：`results/shots/glass-*.jpg`、`blur-*.jpg`。

## Safari 补测（2026-10-21，你在 Mac 上按清单做的）

Safari 26.6.2，也就是 WKWebView 用的同一个 WebKit。

- **毛玻璃**：A 背后的斜纹看不见了，说明普通模糊在真 Safari 里是好的；Playwright 那边“不模糊”只是它自带的 WebKit 的问题。B 没有模糊，和预料一致：带 `url()` 的那条声明被整条丢掉。C 的折射正常，边缘的斜纹被弯折，截图在 `results/shots/glass-safari-c.jpg`。
- **帧率**（窗口 828 × 949，2 倍屏）：四种配置都稳在 60 帧，p95 在 17–18 毫秒，没有超过 33 毫秒的帧。

| 配置 | 帧率 | 平均 | p95 |
| --- | --- | --- | --- |
| 只有星图，带溢光 | 60 | 16.7 ms | 18 ms |
| 加 8 块玻璃 | 60 | 16.7 ms | 17 ms |
| 8 块玻璃，模糊半径 24 | 60 | 16.7 ms | 17 ms |
| 8 块玻璃，不带溢光 | 60 | 16.7 ms | 17 ms |

- **页签换位被拦（2026-10-21 修好）**：页签栏上的落点也会报“左 / 右”方向，我们最初的规则把所有非边缘的左右落点都当成“分出新列”拦掉了，结果同组页签没法换位。改成只拦落在内容区的左右落点后，换位在两种内核下都正常，拦第 4 列、第 4 行的检查照样通过（`probe/reorder.mjs`）。P0.5-06 的布局封装里，3 × 3 的规则只看内容区落点，页签栏上的落点一律放行。
- **拖动手感**：dockview 在 Safari 里拖页签“没那么丝滑”。还没查原因，猜测有三个：拖动时每一组的毛玻璃都要重算；dockview 用的是浏览器原生拖放，WebKit 的拖影和落点提示比较迟钝；落点提示的动画。放进 P0.5-06 排查：拖动期间先关掉各组的模糊看手感变不变；不行再看 dockview 的拖放能不能换成指针事件。
- **拖动手感，P0.5-06-7 的处理（2026-10-21）**：dockview 8 有 `dndStrategy` 选项，可以用指针事件代替浏览器原生拖放，它的文档专门提到某些 Safari 版本和内嵌 WebView 里原生拖放不可靠。工作区封装默认改用指针事件；另外，玻璃面板在 WebGL 背景层上不再用 CSS 模糊，CSS 兜底时拖动期间也暂停模糊。探测脚本 `apps/desktop/probe/workspace.mjs` 用指针事件拖动，32 项在 Chromium 和 WebKit 里全部通过；换回原生拖放，WebKit 有 5 项不过（Playwright 在 WebKit 里模拟不了原生拖放）。手感要在 Safari 和 Tauri 窗口里人工确认：开发版 `#/workspace` 是指针事件，`#/workspace?dnd=html5` 是原生拖放，可以对比。

## Tauri 窗口里的玻璃（P0.5-06-6，2026-10-21）

正式实现在 `apps/desktop/src/ui/glass/`，实验页是开发版的 `#/glass`。在真正的 Tauri 开发版窗口（macOS 的 WKWebView，M1，窗口 828 × 969、2 倍像素）里跑 `#/glass?perf=…&seconds=10`：6 块玻璃面板每一帧都在移动，迫使背景层每帧重画，热身 2 秒后计 10 秒。

| 做法 | 帧率 | 平均 | p95 | 超过 20 ms 的帧 |
| --- | --- | --- | --- | --- |
| WebGL 背景层折射 | 60 | 16.67 ms | 17 ms | 0 / 601 |
| CSS 模糊兜底 | 60 | 16.67 ms | 17 ms | 0 / 601 |

两种做法都贴着 60 Hz 的上限，WKWebView 里看不出差别。这次没有叠首页星图，星图加玻璃的组合留到 P0.5-07 画首页时再在 Tauri 窗口里测一次。

实现上的几点：

- 只有一个全窗口的 WebGL 画布，每一帧读一遍各块玻璃的位置，有变化才重画；窗口不可见时不画。
- 模糊是 7 × 7 次采样，采样网格按像素随机旋转，否则会看到一圈圈波纹。
- 卸载时只释放我们建的对象，不让上下文丢失：React 的 StrictMode 会把同一块画布挂载两次，丢失的上下文不能再用。
- 没有 WebGL、关掉 WebGL 或打开“减少透明度”时，面板自动改用 CSS 模糊或实底。
- 你在 Chrome 里滚动样板间时发现两个问题（2026-10-21）：滚动由合成线程直接完成，背景层要等下一帧才跟上，玻璃下面拖着错位的影子；贴顶的玻璃栏底下滚过正文时，背景层画不出正文，看起来完全透明。处理方式是一条规则：WebGL 玻璃只用在不随内容滚动的外壳上，背后只有壁纸或场景；样板间也改成外壳固定、内容区单独滚动。

## 手测后的修正和压力探测（2026-10-21）

你在 Tauri 窗口里试工作区时报了两个问题：窄窗口时显示不对，拖动页签换位太生硬。顺着查出来的问题和处理：

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 工作区的分组没走 WebGL，玻璃没有颜色，圆角外有一圈方形的浅色 | 开发版的 React 严格模式卸载再挂载一次时，分组的玻璃登记被清空、没再补登；dockview 自己的分组背景盖掉了玻璃的颜色 | 重新挂载时补登已有分组；提高玻璃样式的优先级 |
| 窄窗口里页签标题后面挤出一个“∨ 1” | 页签不会收缩，放不下就进了溢出菜单 | 页签可以收缩到能看见图标和几个字，再放不下才进溢出菜单；竖排时不显示溢出菜单 |
| 分段选择（横排 / 竖排）的字竖着折行 | 没禁止换行 | 不换行 |
| 一格可以被拖得很窄 | 没有最小尺寸 | 每格最少 160 × 96；窗口再窄时该收起侧栏（05 第 2.6 节，P1 外壳做） |
| 换位生硬 | 页签直接跳到新位置 | 落点改成一条插入线；放下时其他页签从原位置滑过去，被拖的页签淡入。dockview 自带的 `tabAnimation: "smooth"` 会让“拖到另一组的某个页签上叠放”失效（8.6.1，指针拖动），所以没用它 |
| 拖影没有样式 | dockview 把拖影挂在页面最外层，不在主题范围里 | 单独给拖影里的页签上样式 |
| 悬浮分组叠在别的内容上，WebGL 画不出它背后的内容 | 同“滚动的玻璃”那条规则 | 悬浮分组用 CSS 模糊 |
| 拉大窗口后壁纸是拉伸的旧图 | 壁纸只在打开时画一次 | 窗口停下 150 毫秒后按新尺寸重画（`useWallpaper`） |
| 睡眠或切换显卡时 WebGL 上下文可能丢失，玻璃会变全透明 | 没处理 | 丢失时改用 CSS 模糊，浏览器恢复上下文后重新走 WebGL |

`apps/desktop/probe/stress.mjs`（`pnpm run probe:stress`）把这些方向写成了检查：四种窗口尺寸和像素密度、拉窄窗口、14 个长标题页签、悬浮分组、深色和减少透明度、字号 125%、反复开关页签和重载布局 10 轮看有没有泄漏、关掉一格的最后一个页签、键盘走到页签、放下时的滑动、叠放、上下文丢失和恢复。Chromium 和 WebKit 各 35 项，全部通过；截图存在 `apps/desktop/probe/shots/`（不提交）。

## 你在 Tauri 窗口里的手测（2026-10-22）

- 圆角外露出方角：来自 dockview 每格外面那层会裁切的直角容器，面板的大阴影超出圆角以后被按直角裁掉。工作区改用小阴影后消失。查的过程中给实验页加了 `?diag`，确认 Tauri 窗口里分组确实走 WebGL、WebGL 层在圆角外画的是干净的壁纸。
- 转角生硬、间距局促：格子里的页签和正文同心内缩，正文是浮在玻璃上的纸，亮边降到六成，间距放宽。
- 分屏、叠放没有过渡：加了布局过渡，留下的格子从原位置平滑移动缩放，新格子淡入。
- 从目录打开开在目录那格：面板登记时分内容和小组件，从小组件里打开的内容开到最近显示过内容的那格。
- 两个页签同时像选中：选中样子只认 dockview 实时更新的类名。
- 系统的“减少透明度”：打开后回到窗口，玻璃变实底；关掉后恢复。你在 Mac 上确认过。
- 外接显示器：你没有第二块屏幕，暂不测。

## 首页星图加玻璃，在 Tauri 窗口里（P0.5-07-3，2026-10-26）

开发版 `#/screens/home?perf&seconds=10`：窗口先设成 1440 × 900（2 倍像素），星图每帧都在转，依次测四种配置，每种热身 2 秒、测 10 秒。

**测的时候这台 Mac 开着低电量模式**（`pmset -g` 里 `lowpowermode 1`），WebKit 在低电量模式下最多每秒 30 帧，所以下面的数字只能比较做法之间的差别，看不出余量。

| 做法 | 溢光 | 第一版 | 改后 |
| --- | --- | --- | --- |
| WebGL 玻璃 | 开 | 23 帧 | 28 帧 |
| WebGL 玻璃 | 关 | 26 帧 | 30 帧（到顶） |
| CSS 模糊 | 开 | 30 帧（到顶） | 30 帧（到顶） |
| CSS 模糊 | 关 | 30 帧（到顶） | 30 帧（到顶） |

- **第一版慢在哪里**：星图在自己的 WebGL 上下文里画，玻璃层是另一个上下文，每一帧都要把整张星图画面传给玻璃层。WebKit 里跨上下文传画面要绕一圈，CSS 模糊都到顶了，WebGL 玻璃还掉到 23 帧。
- **改法**：首页时由星图在同一个上下文里画玻璃，作为它的最后一步，着色器和玻璃层是同一份（`glassFragment`）。玻璃层只负责每帧收集各块玻璃的位置交给星图（`GlassSink`），自己不画。没有了每帧复制，WebGL 玻璃不开溢光时也到顶了。
- 改后还有两次测量窗口中途不在前台，停了几十秒，那两行作废。测量脚本已经改成把超过半秒的停顿单独记下，不算进帧时间。
- **还要做**：关掉低电量模式，在前台再测一次，看真实余量。如果开溢光明显吃力，按原定的降级顺序处理：先关溢光，再降低星图的像素密度（现在最高 1.5 倍），最后在“减少透明度”里关玻璃。Windows 的数字并进 P0.5-11。

## 结论（2026-10-21 确认，已写进 `docs/02-architecture.md` 第 3 节）

1. **无头组件库：React Aria Components。** 键盘操作两边都过关，但 React Aria 多出了我们一定会用到的组合框、自动补全、树、表格、日期、颜色选择、拖放和虚拟列表，输入法组字时不会误选，在 WKWebView 里 Tab 键也能走到每个按钮。代价是体积大一倍（多 50 KB，本地应用可以接受），没有现成的右键菜单（自己接，已验证可行），许可是 Apache-2.0（开源发布时要带上它的 NOTICE）。
2. **图标：Lucide 做默认图标方案。** 覆盖够、线条风格和定稿一致、维护活跃。界面只通过我们自己的图标登记表取图标，不直接引用某个库。这样“图标方案”就能换成 Phosphor 或主题包自带的图标，正好对应设置里的“图标方案”和可扩展性要求。
3. **停靠布局：dockview。** 各项都过，StrictMode 下也正常，拦截钩子好用，皮肤能完全换成我们的玻璃样式。FlexLayout 功能相近、体积更小，但 StrictMode 下拖动失效，不选。我们在外面包一层自己的布局封装，“最多 3 × 3”、页签的三种状态和保存格式都放在封装里，以后要换库只改封装。
4. **折射：用 WebGL 背景层（做法 C），不用 SVG 滤镜。** 壁纸和首页星图本来就由我们自己画，把它们画进一个 WebGL 背景层，各块玻璃面板把自己的位置报给这一层，由它在面板下面画折射和模糊。这样两个平台的效果一致。盖在正文上的浮层用普通 CSS 模糊。CSS 里先写只有模糊的一条作为兜底。
5. **性能：Chromium 有充足余量。** WKWebView 等清单的数字；如果 Safari 明显吃力，降级顺序是：先关溢光，再降低星图的像素密度，最后在“减少透明度”里关掉玻璃。
