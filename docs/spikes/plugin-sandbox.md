# 外部插件的沙箱

2026-11-03 定：外部插件先做沙箱再开放（`docs/extensibility-review.md` 第 2 条）。这里写怎么做、为什么这样能挡住、哪些还挡不住。

## 做法

一个插件就是一个文件夹，装在本机的应用数据目录里（`~/Library/Application Support/dev.dem.desktop/plugins/<id>/`），不进资料库，也不同步。

```
my-plugin/
  manifest.json   名字、版本、要什么权限、有哪些面板和命令
  index.html      面板和后台都打开这一页
  ...             脚本、样式、图片、WebAssembly 都可以
```

- **装上不等于启用**：在设置的“插件”里点启用，会先列出它要的权限，同意了才启用。插件更新后多要了权限，会自动停用，等你重新同意。
- **运行在隔离的 iframe 里**：`sandbox="allow-scripts"`，不给 `allow-same-origin`，所以它的来源是不透明的。它读不到软件页面里的任何东西，也拿不到本地存储。页面通过软件自己的 `jadyplugin://` 协议加载，每个响应都带内容安全策略：只能加载 `jadyplugin:` 下的文件，不能联网（`connect-src 'none'`），不能嵌套页面，也不能提交表单。允许 WebAssembly。
- **只能通过消息调用受控接口**：插件用 `/_sdk/jady.js` 发消息，软件按消息来自哪个 iframe 认出是哪个插件，再转给 Rust 端的 `plugin_call`。Rust 端按你批准的权限和隐私层级检查，查的是 `dem-core` 的门面，和 AI 的普通会话用同一套受限视图。
- **不能把自己跳到外网**：iframe 的每次跳转都经过 WebKit 的导航判断，软件只放行自己的页面和插件协议。

## 权限

| 权限 | 能做什么 |
| --- | --- |
| `items:read` | 搜索、列出、读取普通内容。敏感、私密、机密、回收站和密码库一律看不到，和普通 AI 对话一样 |
| `items:create` | 新建条目，只能建默认隐私是普通的类型 |
| `items:write` | 修改它能读到的条目：标题、正文、标签、字段。不能删除，不能改隐私层级、状态和位置，不能改系统条目 |

不用申请的：自己的面板和命令、提示消息、打开它能读到的条目、一块自己的存储（存在库的本机设置里，最多 1 MB）。

现在不给的：联网、调用 AI、敏感内容、改设置。以后要加，先在这里写清楚怎么挡，再加权限名。

## 为什么挡得住

- **调用通道**：Tauri 每次启动随机生成调用密钥，只注入主页面（`for_main_frame_only`）；没有密钥的调用一律拒绝（`tauri/src/webview/mod.rs` 的 `on_message`）。插件的 iframe 拿不到这个密钥，又因为来源不透明，也读不到主页面的变量。
- **网络**：插件页面的内容安全策略由软件的协议加在响应头上，插件改不了。
- **冒充**：插件之间能互相发消息，所以 SDK 只认来自父页面的消息，软件只认来自自己创建的 iframe 的消息。
- **数据**：检查都在 Rust 端。即使界面层出了错，`plugin_call` 也只交出受限视图里的东西。

## 还挡不住的

- **DNS 预解析之类的旁路**：内容安全策略管不到，可能漏出极少量信息。插件能读到的本来就只有普通内容。
- **界面欺骗**：插件的面板能画成任何样子，比如画一个假的“输入主密码”。所以面板外框始终显示插件名，主密码永远不会在插件面板里要。
- **资源占用**：死循环会拖慢它所在的页面。WebKit 会把同源页面放在同一个进程里，所以可能拖慢整个窗口。停用插件就能恢复。

## 和 M12 的差别

M12 写的是“逻辑编译成 WebAssembly，界面运行在隔离容器里”。实际做法是逻辑和界面都在隔离的 iframe 里，插件愿意的话可以在里面跑 WebAssembly。隔离靠的是浏览器的来源隔离和内容安全策略，不靠 WebAssembly；分成两套运行环境，只会让写插件更难，安全上没有多得什么。

## 构建时带上的插件

`src/plugins/<name>/` 的方式保留，给想改软件本身的开发者用。它和软件权限一样大，不经过这里的检查。
