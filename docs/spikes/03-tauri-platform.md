# 技术验证 03：Tauri 平台能力（P0-12）

- 日期：2026-10-17 至 2026-10-18
- 机器：Apple M1，macOS 26.6.2（25G83），APFS；WKWebView 21624.5.1.11.3
- Rust 1.99.1；tauri 2.12.4、tauri-build 2.7.3、tauri-plugin-global-shortcut 2.4.1（内部 global-hotkey 0.8.0）、tauri-plugin-notification 2.7.0（内部 notify-rust 4.18.2、mac-notification-sys 0.6.15、Windows 用 tauri-winrt-notification 0.8.1）、keyring-core 1.0.1、apple-native-keyring-store 1.0.2、windows-native-keyring-store 1.1.0、security-framework 3.7.0、getrandom 0.4.3、sha2 0.10.9
- 前端：@tauri-apps/api 2.12.4、@tauri-apps/cli 2.12.3、Vite 8.3.4、TypeScript 6.0.3、pnpm 12.9.1、Node 26.10.0
- 代码与复现方法：`spikes/platform/`（见其 README）；原始输出：`spikes/platform/results/`
- **说明**：本次在 macOS 上无人值守执行，执行时屏幕处于锁定状态。凡是需要按键、点击、看对话框的项目都**没有测**，已写进清单；Windows 部分全部待你按清单执行。

## 要回答的问题

1. 全局快捷键：能否注册、注销；冲突时会不会报错、报什么错；应用在后台时按下能否把窗口叫到最前。
2. 系统通知：是否需要申请权限；能否显示；点击通知后能否回到应用并知道点的是哪条。
3. 钥匙串：能否在 macOS 钥匙串和 Windows 凭据管理器里存、取、删一个 32 字节的密钥；耗时多少；**未签名的版本重新构建后还能不能读到**（格式规范第 1 节问题 7）。

## 做法

- **`hotkeyprobe`**：直接用 Tauri 插件底下的 `global-hotkey` 0.8.0，不需要按键就能测注册结果：同一进程重复注册、另一个进程已占用、系统和常见软件已占用的组合、注销后再注册。
- **`keyprobe`**：用 `keyring-core` + 各平台原生存储。密钥由 `getrandom` 生成；程序只输出长度和 SHA-256 前 6 字节的指纹，从不输出密钥本身，错误信息里带原始字节的变体也只输出长度。Windows 上指定 `persistence=Local`（只存本机，不随域账户漫游）。
  - “未签名重新构建”的复现：编译时注入 `KEYPROBE_BUILD_TAG`，不同标签产生不同的二进制（不同 CDHash）。用 A 写入，再用 B 读取。
- **Tauri 探测程序 `app/`**：一个窗口，Rust 端提供快捷键注册/注销（经插件）、隐藏/最小化/延时自己弹出、通知（经插件，带点击回调）、钥匙串存取删、保存报告；前端把每一项结果写进页面上的结果表，可截图、复制或保存到桌面。设置 `DEM_PROBE_AUTORUN=<文件>` 时自动跑完所有不需要人的检查、写出报告并退出，本次 macOS 结果就是这样采集的。
- 打包：`pnpm tauri build` 产出 `.app` 和 `.dmg`，用 `codesign`、`spctl`、`syspolicy_check` 检查签名和 Gatekeeper 评估。
- **Windows 预编译检查**（在 Mac 上，只做类型检查，不链接、不运行）：`cargo check --target x86_64-pc-windows-msvc --all-targets`。四个程序（含 Tauri 应用、Windows 凭据存储、全部测试）都能通过，说明 Windows 上不会卡在编译错误；Tauri 应用的资源编译步骤在 Mac 上用了一个空的替身，真实的图标和清单资源要到 Windows 上才编。

## 数据

### 全局快捷键（macOS，`results/macos-hotkeyprobe.md` 与 `results/macos-app-unattended.md`）

| 情况 | macOS 结果 |
| --- | --- |
| 首次注册 | 成功，约 0.15～0.3 毫秒 |
| 同一进程再注册同一组合 | 报错：`FailedToRegister: RegisterEventHotKey failed for KeyK`（插件里显示为 `Unable to register hotkey: …`），插件的 `is_registered` 能提前查到 |
| 注销、重复注销、注销后再注册 | 都成功（重复注销也不报错） |
| **另一个进程已注册同一组合** | **注册成功，不报错** |
| 系统或常见软件已占用的组合：⌘Space（聚焦搜索）、⌘Tab、⌘⇧3（截屏）、⌃Space（切换输入法）、⌥Space | **全部注册成功，不报错** |
| 无法识别的键名 | 报解析错误 |
| 按下快捷键、后台呼出窗口 | **未测**（需要人按键，见清单） |

macOS 用的是 Carbon 的 `RegisterEventHotKey`，`global-hotkey` 调用时不带“独占”选项，所以系统只在**同一个应用里重复注册**时报错；别的应用或系统已经占用时照样“成功”，按下时谁收到要靠人测。Windows 用 `RegisterHotKey`，源码里对 `ERROR_HOTKEY_ALREADY_REGISTERED` 有专门处理，预期别的程序占用时会报 `AlreadyRegistered`；2026-10-19 Windows 实测证实。

### 钥匙串（`results/macos-keychain.md`）

| 项目 | macOS 结果 |
| --- | --- |
| 旧式登录钥匙串：存 / 取 / 覆盖 / 删 / 删后再取 | 全部成功；存 22～108 毫秒，取 1.7～15.8 毫秒，删 19～31 毫秒，删后取得 `NoEntry` |
| 连续读取 100 次（每次新建条目对象） | 中位 1.17 毫秒，95% 2.12 毫秒，最大 5.18 毫秒 |
| Tauri 应用包内存取删 | 全部成功（存 97.1、取 1.7、删 19.2 毫秒） |
| 受保护数据存储（protected，`kSecUseDataProtectionKeychain`） | 失败：“A required entitlement isn't present”。需要带团队编号的正式签名和描述文件，未签名程序用不了 |
| **同一个二进制复制到别的路径再读** | 成功（身份看 CDHash，不看路径） |
| **改了代码重新构建（未签名，链接器自动加的临时签名）再读** | **卡住**：25 秒内没有返回，系统启动了 `SecurityAgent`（钥匙串授权对话框的进程）。屏幕锁着，对话框内容没看到 |
| 原样重新构建（字节相同、CDHash 相同）再读 | 成功 |

| 另一个程序（`security delete-generic-password`）删除本程序的条目 | 直接删掉，不弹框 |

Windows 凭据管理器：2026-10-19 实测证实下面的预期。按微软文档，普通凭据没有“按程序授权”的概念，同一用户下的任何程序都能读，所以预期重新构建不影响读取，但同时也意味着别的程序同样能读到。

### 打包与签名（macOS）

| 构建 | `codesign --verify` | Gatekeeper（`spctl`，加隔离属性模拟下载） |
| --- | --- | --- |
| 默认（不配置签名） | 包内二进制只有链接器临时签名，`Info.plist not bound`；整个包**校验失败**：“code has no resources but signature indicates they must be present” | rejected。按经验，下载后打开会提示“已损坏，应移到废纸篓”，不能用“仍要打开”绕过（这一点没有实际下载验证） |
| `bundle.macOS.signingIdentity = "-"`（临时签名整个包） | `valid on disk`，`satisfies its Designated Requirement`，带 hardened runtime 标志 | rejected（未公证），`syspolicy_check` 报“临时签名”“缺公证票据”。按 Apple 官方说明，可以在“系统设置 → 隐私与安全性 → 仍要打开”放行一次 |

- DMG 打包在锁屏/无图形会话时失败（Finder 的 AppleScript 超时 -1712）；设 `CI=true` 后跳过排版步骤即可成功。release 构建：首次约 10 分钟（编译全部依赖），之后约 1 分钟；`.app` 12 MB，`.dmg` 4.5 MB。

## 结论

| 能力 | macOS | Windows |
| --- | --- | --- |
| 全局快捷键注册/注销 | **可行**。不需要辅助功能权限 | **可行**（Windows 11 25H2 实测） |
| 冲突报错 | **只能发现本程序内部的重复**；别的程序或系统占用时不报错，属于静默冲突。人工补测确认：与另一程序抢 ⌘⌥⇧J、与系统“选择上一个输入法”抢 ⌃Space，注册都成功，按下时本程序收到，系统输入法**不再切换** | **能报错**：别的程序已占用时报 `HotKey already registered`；Win+L、Win+E、Alt+Tab、Ctrl+Shift+Esc、Ctrl+Alt+Del 注册失败。但 **Ctrl+Space、Alt+Space 能注册成功**，按 Alt+Space 呼出的是本程序，系统窗口菜单不再出现 |
| 后台呼出窗口 | **可行**：从访达呼出、隐藏后呼出、最小化后呼出都回到最前并获得焦点；程序 5 秒后自己调用也会跳到最前（不只是程序坞图标跳动） | **可行**：从别的程序、隐藏后、最小化后都能呼出并获得焦点；程序 5 秒后自己调用也跳到最前（该项由合成输入触发，前台锁可能被放宽，真人操作时待复核） |
| 通知显示 | **可行**：在系统设置里打开通知后正常弹出。之前通知为“关闭”时，没有询问框、也不显示，插件却照样返回成功 | **可行**，程序名和图标正确 |
| 通知点击回到应用 | **不行**（插件 2.7.0）：通知弹出、用户点击后，程序没有收到点击事件，窗口也没有回到最前 | **可行**：点击后回到最前，收到 `click-back`（`action tap`）。从通知中心点击按用户口述正常，缺日志佐证 |
| 通知权限 | 插件**无法查询真实状态**：人工补测时系统设置里是“关闭”，Rust 接口和网页接口都报“已授权” | 同 macOS：关掉通知后仍报“已授权”，`show` 仍返回成功，程序察觉不到 |
| 钥匙串存取删 32 字节 | **可行**，读取约 1～2 毫秒，远低于“日常打开 ≤ 200 毫秒” | **可行**（凭据管理器），读取 p50 0.13 毫秒；`cmdkey /list` 能看到条目名，持久性为“本地计算机” |
| 未签名重新构建后读取 | **不行**：每次代码变化后的第一次读取会弹系统授权框，在用户回应前一直阻塞（实测等了 19.5 分钟）。“始终允许”只对当次的二进制有效，换一个版本又会弹框；点“拒绝”时约 1.8 秒内返回错误 `PlatformFailure: User canceled the operation`，不会卡住 | **不受影响**：换版本读取不弹窗；安装版写入的条目，开发版也能直接读到（指纹相同） |

建议：

1. **快捷键冲突**：软件不能依赖系统报错来发现冲突。M11 的“修改时检查冲突”只能检查软件自己的快捷键表；对全局快捷键，在设置界面提示“如果按下没反应，可能被别的程序占用”，并提供一个“按一下试试”的检测按钮。默认的全局快捷键避开 ⌘Space、⌃Space、⌥Space。
2. **钥匙串**：
   - 正式版：用旧式登录钥匙串（`keychain` 功能），不用受保护数据存储。读取必须放在后台线程，并设超时；超时或被拒绝时退回“输入主密码”，界面不能卡死。
   - 开发阶段：每次重新构建都会弹框。建议**开发版使用独立的钥匙串条目名**（例如服务名带 `.dev` 后缀），并提供“开发版不使用钥匙串、每次输主密码”的开关，正式库的主密钥不交给开发版。如果你希望开发版也能免密，需要一个受信任的自签名代码签名证书（要你在“钥匙串访问”里手动创建并设为信任），或者 Apple 开发者账号的证书；两者都需要你决定。
   - 安全含义：macOS 上别的程序能**删除**我们的条目（只是没法读），所以钥匙串只能当“方便”，不能当唯一的密钥来源；主密码和恢复码仍是根本。Windows 上同一用户的任何程序都能读凭据，这一点要写进格式规范的威胁模型。
3. **打包**：P0-06 的 macOS 打包应设置 `bundle.macOS.signingIdentity: "-"`，否则下载后的 `.dmg` 里的程序是“已损坏”状态。无图形会话的构建（CI）设 `CI=true`。
4. **通知**：提醒（M8）可以用插件 2.7.0 的点击回调实现“点通知打开对应条目”；权限状态拿不到，界面上要提示“如果收不到提醒，请检查系统通知设置”。

## 对文档和格式的影响

- **格式规范第 4 节（钥匙串条目命名）**：服务名用应用标识加用途，例如 `dev.dem.desktop` / 账户 `vault:<库编号>:master`；开发版用 `dev.dem.desktop.dev`。Windows 上目标名默认是“账户.服务”，规范里写明拼接方式，并规定 `persistence=Local`。

- **04-phases.md / P0-06**：macOS 打包加 `signingIdentity: "-"`；CI 上 `CI=true`。

## Windows 实测（2026-10-19）

在 Windows 11 专业版 25H2 台式机上由 Claude Code 执行清单，需要看屏幕的项由你观察确认。填好的清单和原始输出在 `spikes/platform/results/windows/`（`03-filled.md`、`04-filled.md`、`README.md`）。结论已并入上表，与 macOS 的主要差别：

- **快捷键冲突**：Windows 上与别的程序冲突时会报错，macOS 不会；但两边都能悄悄占用部分系统组合（macOS 的 ⌃Space，Windows 的 Ctrl+Space、Alt+Space）。
- **通知点击**：Windows 上能回到程序，macOS 上不行（插件 2.7.0）。
- **凭据**：Windows 不会因为重新编译而弹窗，同一用户下的任何程序都能读到（已写进威胁模型）。
- **开发版与安装版**：identifier 相同时共用 WebView2 数据目录，两者同时运行时启动参数必须一致，否则后启动的那个直接退出、不报错。开发版建议用不同的 identifier（例如加 `.dev`）。
- **`pnpm tauri dev` 卡住**：Vite 只监听 `::1`，Tauri 等的是 `localhost`，与代理无关。已把主程序和探测程序都改为明确监听 `127.0.0.1`。
