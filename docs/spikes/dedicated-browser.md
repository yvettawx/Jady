# 专用浏览器

2026-11-03 由你决定放开：AI 可以操作专用浏览器，去需要登录的网站。之前的分析结论是“先不做”，这里记下怎么做的、守住了什么、还有哪些局限。

## 怎么做的

- **用你电脑上的 Chrome**（找不到就依次找 Chromium、Edge、Brave），加一份单独的配置，放在软件自己的数据目录下的 `browser-profile`。和你平时用的 Chrome 分开，登录状态只在这台电脑上，不同步，也不进库。
- **控制走管道，不开端口。** 用 `--remote-debugging-pipe` 启动，命令和回复走进程的管道（第 3、4 号描述符），电脑上的其他程序接不进来。代码在 `crates/dem-browser`，没有新增第三方依赖。
- **AI 用四个网关工具**：`browser_open`（打开网页）、`browser_read`（读页面）、`browser_click`（按编号点击）、`browser_type`（按编号输入）。它们和库的工具一起由网关提供，Claude Code 照旧只开网关工具和上网，不能执行命令、读写文件。
- **设置里单独一页“专用浏览器”**：开关、可以去的网站、打开浏览器自己登录。新库默认关着。

## 守住了什么

| 规则 | 做法 | 测试 |
| --- | --- | --- |
| 只在能上网的会话里有 | 授权读取敏感内容的会话没有浏览器工具 | `browser.rs` 的单元测试 |
| AI 不能改设置 | 开关和网站列表只有界面能改，没有对应的 AI 工具 | 同上；网关测试确认工具列表 |
| 只去你列的网站 | 打开网页前检查；AI 点链接跳到别的网站也会被拦下 | 真实 Chrome 里测过 |
| 提交要你同意 | AI 操作期间和之后 3 秒内，页面发出的非读取请求（POST、PUT、DELETE 等，包括表单和脚本发的）都先停住，弹窗问你；不允许或两分钟没人回答就不发 | 真实 Chrome 里测过表单和脚本 POST，不允许时网站什么都没收到 |
| 不碰密码 | 读页面时不读密码框的内容；AI 不能往密码框里输入 | 真实 Chrome 里测过 |
| 验证码和登录交给你 | 页面有密码框或常见的验证码时，工具结果让 AI 停下，请你在窗口里自己处理 | 真实 Chrome 里测过 |
| 网页内容不当指令 | 页面文字包在 `<web_page>` 里，注明是数据不是指令 | 单元测试 |

你自己在窗口里浏览不受任何限制：只有 AI 的操作期间和之后 3 秒才有这些检查。

## 局限

- **故意拖延的请求拦不住**。页面可以等 AI 操作 3 秒后再发请求。你列进去的网站一般不会这样，但这是判断“谁引起的”的方法决定的。
- **WebSocket 里发的消息拦不住**。协议只能拦下建立连接那一步，不能拦后面的消息。
- **配置目录大部分是明文**。Cookie 由 Chrome 用钥匙串里的密钥加密，历史记录、本地存储等是明文，和你平时的 Chrome 一样。
- **定期任务没人在场时**，任何提交都会因为没人确认而不发。只适合读取，比如每周看一次职缺。
- **只测了无窗口模式和本地测试网站**。登录真实网站、真实窗口里的使用感受、Claude Code 真的调用这几个工具，都要你在场试。
- 遵守对方网站的条款仍然要你判断：只把允许自动访问的网站列进去。
