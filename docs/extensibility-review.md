# 可扩展性检查（P5 第 1 步）

2026-11-03 对照“任何人读文档或让 AI 读 SKILLS，就能自己扩展”检查了一遍。

## 已经通的

都走同一套登记机制，内置功能和插件用的是同一个入口，都有文档和能跑的例子（`apps/desktop/src/plugins/_example/`）。

| 能加什么 | 怎么加 | 文档 |
| --- | --- | --- |
| 面板、命令、启动器结果、首页小组件、左栏视图、设置分区、每周复盘步骤 | 插件 `ctx.register*` | `docs/extending/plugin-api.md` |
| 配色和图标方案 | 插件或主题令牌 | `docs/extending/theming.md` |
| 模板 | 插件 `ctx.registerTemplate` | `docs/extending/templates.md` |
| AI 提供者 | 实现 `AiProvider`，改代码重新构建；内置四种，DeepSeek、本地模型这类兼容 OpenAI 的不用写代码 | `docs/extending/ai-provider.md` |
| 类型、字段、快捷键、配色、字体、自定义 CSS、首页布局、AI 工作约定 | 软件里直接改 | `docs/extending/README.md` |
| 其他程序调用 | `dem` 命令行、`dem://` 链接 | `docs/extending/automation.md` |

这一轮做的：插件接口加了版本号（`PLUGIN_API_VERSION`），插件要求的版本比软件新时不启动；模板能由插件登记；时间轴、统计、地图只看字段，不认具体类型，所以手工建的类型也能用。

## 还没通的

| 缺口 | 影响 | 建议 |
| --- | --- | --- |
| ~~插件只能构建时带上~~ | 2026-11-03 做了外部插件：从文件夹安装，在沙箱里运行 | 见 `docs/extending/external-plugins.md` |
| 外部插件能用的界面能力还少 | 只能加面板和命令，加不了首页小组件、侧栏视图、设置分区和配色 | 有人需要时，在消息接口里加，照样走权限检查 |

| 模板只能带类型和起步内容，带不了提醒规则和视图配置（M12 写了要带） | 习惯模板没有“今天没打卡”的提醒，靠首页小组件 | 提醒规则做成数据后再加 |

## 外部插件怎么加载（2026-11-03 定了第 2 条，已做）

做法和为什么挡得住，见 `docs/spikes/plugin-sandbox.md`。当时的两条路：

1. **先放开，靠提示**：从 `插件` 文件夹加载 JS，第一次启动时明确提示“插件权限和软件一样大，能读你解锁的所有内容”。做起来快，但要放宽内容安全策略，风险全在用户身上。
2. **先做沙箱**：插件运行在隔离的 iframe 里，只能通过消息调用受控接口，遵守隐私层级。安全，但界面能力受限，工作量大。

我建议第 2 条，开源前不开放外部加载。这个软件存着私密内容和密码库，第 1 条一旦有人装到恶意插件，后果无法挽回。在此之前，构建时带上的方式已经够开发者用。
