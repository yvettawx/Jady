## 总原则

- **存储格式和数据模型一次做对，功能可以分批做。** 功能以后补很容易；格式一旦改动，就要迁移全部历史数据。
- **每个阶段结束时都是一个可以用的状态**，不留半成品在主分支上。
- **先验证、后建造**：有不确定性的技术点，先用小程序验证，再写正式代码。
- **平台**：先 macOS，很快扩展到 Windows。从 P0 起，构建流水线就同时产出两个平台的版本。
- **面向将来的其他用户**：先自用，P5 开源发布。每个阶段都不写死个人内容，界面文字放语言资源文件，默认设置面向新用户（2026-10-19）。

```mermaid

  P0["P0 开发工具<br/>格式转换、查看器<br/>测试、技术验证"] --> P05["P0.5 设计<br/>交互规范、视觉系统"]
  P05 --> P1["P1 基础软件<br/>第一个能每天用的版本"]

  P4 --> P5["P5 开源发布<br/>可扩展性、引导、签名、更新"]
```

## P0 开发用的辅助工具

### 目标

搭好开发和验证的基础设施，确认关键技术可行，写出格式规范初稿。P0 不产出给我日常使用的功能。

### 步骤

1. **建立仓库骨架**：按《模块说明》M0 的结构建 Cargo 工作区和 Tauri 应用空壳；配好格式化、静态检查、测试命令。
2. **构建流水线**：仓库保持公开；每次推送在云端（GitHub Actions）的 macOS 和 Windows 上都跑检查和测试，本地用 `cargo xtask ci` 跑同一套检查；打标签时两个平台都打包，另留一个手动触发的 Windows 打包供真机测试。（2026-10-18 确认）
3. **技术验证**（每项一个独立的小程序，结论写进 `docs/spikes/`）：
   - CRDT 库和编辑器的配合：Loro 与 Automerge 各做一次，比较富文本编辑、版本对比、可移动树、文件体积增长、上万条目时的性能，以及格式稳定性承诺。产出选型结论。
   - SQLite 自定义分词：中文单字加相邻两字、繁简互通、忽略重音；配合 SQLCipher。
   - Tauri 的全局快捷键、系统通知、系统钥匙串，在 macOS 和 Windows 上分别验证。
   - Windows 差异点：WebView2 渲染与 macOS WebKit 的差异、文件路径和大小写规则、未签名安装包的系统提示。
   - Claude Code 无交互模式加 MCP：从程序里启动、流式读取输出、接入一个本机 MCP 服务、收紧权限后确认无法执行命令和读写文件、跑通一次“读取 → 提议修改”。
4. **格式规范初稿**：库目录结构、加密封装、CRDT 文档的逻辑结构、日志格式、隐私层级规则（依据《模块说明》M2、M9）。
5. **开发工具**（放在 `dem-devtools`）：

| 工具 | 用途 |
| --- | --- |
| 格式转换器 | 内部格式和 Markdown、JSON 互转，也是以后导入导出的基础 |
| 库查看器 | 命令行工具，解密并打印条目、关系、日志和修改历史，方便调试 |
| 格式校验器 | 检查库文件是否符合格式规范，发现损坏 |
| 测试数据生成器 | 按类型批量生成假数据，包括中文、西夏文、历史日期，用来测试搜索和性能 |
| 索引重建与比对 | 从原始数据重建索引，并和现有索引比对（P0 只搭框架，重建在 P1 接入 `dem-index`） |
| 格式迁移测试 | 格式版本升级时自动验证数据不丢失（P0 只搭框架） |
| AI 网关调试台 | 模拟 Claude 调用网关工具，检查隐私过滤和提议是否正确，不消耗订阅额度 |
| 性能基准 | 上万条目时的打开、搜索、保存耗时 |
| 自动化测试框架 | 单元测试、集成测试，以及对 CRDT 合并、加密解密、格式读写的随机化测试 |
| 损坏与恢复演练 | 模拟文件损坏、索引丢失、用恢复码解锁，确认数据都能找回 |
| 搜索评测集 | 固定的查询和期望结果，覆盖中文、繁简、西夏文、重音符号（P0 只搭框架） |
| AI 回归测试集 | 固定场景，检查隐私不泄露、提议格式正确、“本次收获”提取质量；会消耗额度，只在改动 AI 相关部分时运行 |
| 本地诊断日志 | 出错时在本机记录日志和诊断信息，不上传 |

说明：AI 网关调试台和 AI 回归测试集在 P0 先搭框架，随 P3 的网关一起完善；索引重建与比对、格式迁移测试、搜索评测集在 P0 也只搭框架。

### 交付物

- 能在两个平台构建的仓库骨架和流水线
- `docs/spikes/` 下的技术验证结论，含 CRDT 库选型
- 格式规范初稿 `docs/format-spec.md`
- 上表中的开发工具（标明“只搭框架”的几项为框架）

### 完成标准

- CRDT 库选定，并通过性能基准的初步测试。
- Claude Code 加 MCP 的读写流程跑通，且权限收紧有效。
- 格式规范初稿经我确认。

## P0.5 设计

### 目标

定下整个软件的设计语言，包括交互（HCI）和视觉，给 P1 起的所有界面工作打地基。定位为“半系统”：设计规范按操作系统设计规范的级别来做，规定以后每个新模块、内容类型、插件怎样长出来。P0.5 不做业务功能。（2026-10-19 新增）

### 步骤

详细任务见 `docs/plans/p0.5.md`。

1. **交互方向探索**：几轮可操作原型，比较操作逻辑和排布；选定可停靠工作区为骨架，加上 Arc 的操作逻辑。
2. **交互规范**：空间结构、面板、标签、打开方式、启动器与指令、AI 交互、编辑、快捷键、新手引导、多语言，写进 `docs/05-design.md`。
3. **视觉系统**：设计原则、令牌（颜色、字体、间距、动效）、组件、关键界面；界面组件库的技术验证（结论写进 `docs/spikes/`）。
4. **正式代码**：令牌和基础组件进入正式代码，开发版里有一个样板间页面。
5. **双平台检查**：在 macOS 和 Windows 上检查样板间和快捷键。

### 交付物

- `docs/05-design.md` 设计规范（交互和视觉）
- 令牌和基础组件的正式代码、样板间
- P1 范围的高保真界面稿，P3 关键 AI 界面的中保真稿

### 完成标准

- 设计规范定稿，经我确认。
- 令牌和基础组件进入正式代码，深浅色无遗漏颜色。
- 快捷键初版表在两个平台上实测过。

## P1 基础软件

### 目标

第一个能在一台电脑上每天用起来的版本。没有 AI。

### 包含的需求

A1、A2、A3、A4、A5、A7、A11、A12（基础版）、A13（全局快捷键部分）、B1、B5、E1、E3（不含推送）、F1（不含密码库）、F2、F4、F5、H1、H2、H3

### 步骤

1. **数据模型**（M1）：条目、类型定义、内置类型、灵活日期、关系、组织结构。
2. **存储**（M2、M9）：库的创建和打开、密钥体系、加密封装、条目 CRDT 文件、附件、活动日志、原子写入、版本历史。开发版不做代码签名：每次重新构建后读钥匙串会弹授权框，由我点允许或输入主密码（M9）。
3. **索引与查询**（M3）：索引表、自定义分词、结构化查询、反向链接、热度图统计。
4. **核心服务门面**（M0、M5）：条目增删改查、移动、归档、收集箱、待办状态；受限视图的接口先定好（AI 在 P3 才用）。
5. **桌面外壳**（M11）：Tauri 应用、工作区布局（按 `docs/05-design.md`：一切都是面板、可切分拖动、空间）、启动器、快捷键、深浅色主题、全局快捷键收集框；界面文字放语言资源文件（H7 的结构）。
6. **编辑器**（M11）：富文本、CRDT 绑定、内链、Mermaid 和 SVG 图、段落拖动。
7. **视图**（M11）：列表、表格、看板。
8. **首页、待办与提醒**（M5、M8、M11）：欢迎词、热度图、今日待办、规则提醒和系统通知。
9. **自定义类型基础版**（M1）：建类型、加字段，配合表格和看板。
10. **导入导出**（M4）：CSV、Excel、Markdown 导入；单篇 Markdown、PDF 导出，一键导出全部；PDF 和幻灯片文字提取。
11. **版本对比**（M2）：选两个版本并排对比，给版本起名。
12. **隐私层级**（M9）：四级字段、层级继承；机密内容打开前再验证（建议）。
13. **打磨**：用真实内容试用一段时间，修问题。

### 必须一次做对、以后很难改的

数据模型和类型系统、条目 CRDT 文件格式、加密方式、日志格式、“只有一个出口”的数据访问层。即使 P1 暂时用不上（比如还没有 AI、还没有同步），也要按最终的样子设计。

### 进度（2026-11-02）

步骤 1 到 12 都有了，可以打包使用，还差的记在 `docs/review/` 的“没做完的”。步骤 13（用真实内容试用）要我来。端到端测试：`pnpm run probe:app`。

### 完成标准

- 我能用它每天记录、整理、管理待办，并持续使用至少两周。
- 删除索引能完整重建；拿走库文件无法读出内容。
- 能导入现有的职缺数据库，并在表格和看板里使用。
- macOS 版本能正常使用（2026-11-02：目前只做 Mac，Windows 以后再做）。

### 目标

让 GTD 循环和长期组织真正运转起来。

### 包含的需求

A9、A10、A13（其余收集渠道）、E4（不含 AI 起草）、E5（不含掌握度引用）、E6 和 E8 的记录部分、F7、H4、H5

### 步骤

### 完成标准

- 命令行能新增和查询内容，且默认不输出私密和机密内容。

## P3 学习与 AI

> **进度（2026-11-03）**：P2、P3 都做了，还差的记在 `docs/review/`。P2 完成标准里的“坚持数周”要我来。隐私和权限用金丝雀测过两层：`dem-dev gateway-sim --target real` 和 `probe/real-ai.mjs`（真实 Claude Code）。

### 目标

AI 全面接入，学习引擎上线。

### 包含的需求

A6、A8、B2、C1–C9（C6 的推导重建、C7 的沙盒运行除外）、D1–D9、D12、D13、E4 的 AI 起草、E5 的掌握度引用、E6 的 AI 识别、E7、E8 的 AI 小结

### 步骤

1. **AI 网关**（M6）：受限视图、工具清单、提议队列、AI 访问记录；先用 P0 的网关调试台把隐私规则测透，再接真实 AI。
2. **AI 提供者**（M6）：Claude Code 子进程（用户自己登录）、API key 直连；流式输出、权限收紧、会话延续；用量显示；设置里选择接入方式（D14）。启动参数见 `docs/spikes/05-claude-code-mcp.md`；Claude Code 版本变化后自动跑隔离自检。
3. **工作约定、会话与收尾**（M6）：三级约定的叠加、会话记录、摘要、待补清单、“本次收获”确认流程。
4. **AI 侧栏与修订界面**（M11、M6）：对话面板、提议审核（改动前后对比、授权选项）、撤销。
5. **学习引擎**（M7）：FSRS 排期、复习记录、偷看和把握、掌握度、学习项目与冲刺、方法推荐。
6. **学习零件**（M7）：记忆卡复习、AI 讲课（含摸底和资料搜集）、实时对话（以法语示例为验收场景）、精读与批注、对照文本、渐进背诵。
7. **做题**（M7）：作答界面、语言服务器检查、编译检查、AI 判断、错题和错误模式、模拟考。
8. **AI 增强的日常管理**（M5、M6）：定期维护、子弹笔记识别、间隙日志小结、回顾起草、每日规划、常青笔记建议。
9. **知识检索**（M6、M3）：工具检索；用真实数据测试，决定是否加本地向量检索。
10. **来源标记和罕见文字**（M1、M11）：来源和把握、复查日期提醒；西夏文等字体和字符面板。

### 完成标准

- 隐私测试全部通过：私密、机密和密码库从未出现在 AI 可见的结果里；敏感内容只在授权会话中出现。
- 法语实时对话示例完整走通。
- 一次“考前冲刺”从摸底、讲课、做题到转入长期复习完整走通。
- AI 的任何改动都能撤销。

## P5 开源发布

### 目标

在我自己用稳定之后，把软件开源、免费推广给其他人。（2026-10-19 新增）

### 包含的需求

H7（英文界面）、H8、D14 的插件提供者，以及发布所需的工程工作

### 步骤（顺序可按当时需要调整）

1. **可扩展性检查**：命令、插件、面板、主题包、AI 提供者，目标是用户可以完全自定义软件的样式和行为；插件接口定稳。
2. **设置与新手体验检查**（单独一轮，排在可扩展性检查之后，2026-10-19 确认）：逐项检查设置里有什么、怎么分组、说法是否好懂；每个默认设置是否适合第一次用的人；新手引导（H8）和起步模板做完整：建库、选语言、设置 AI 接入（检测本机的 Claude Code，或填 API key，也可以先跳过）、选模板；空状态和第一次打开时看到的内容；去掉一切个人内容。
3. **英文界面**（H7）。
4. **代码签名与公证**：macOS 公证、Windows 签名，去掉未签名安装包的系统拦截。
5. **自动更新**，以及格式升级时的迁移。
6. **其他 AI 提供者**：Codex、DeepSeek、本地模型等（D14）。2026-11-03 内置了 Codex 和 OpenAI 兼容接口（DeepSeek、Ollama、LM Studio 都走它）；别的以插件加入。
7. **条款复查**：重新查阅 Anthropic 和其他提供者的条款；确认在产品里运行 Claude Code 的商业条款怎么办。
8. **文档与社区**：用户文档、开发者文档（插件、格式规范）、许可证、贡献指南。
9. **仓库重新公开前的清理**（2026-10-21 起仓库是私有的）：
